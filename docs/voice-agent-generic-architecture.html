通用語音助理架構

拿掉表單邏輯，只留骨架 —— 給任何用途的語音助理用，不綁定特定業務

1骨架 vs 內容，這次明確切開

項目去留說明
身分驗證流程留「驗證是誰、換一組短效通行證」這套機制留著，裡面認證的對象從「只認 LINE」改成可以換
跟語音 AI 換通行證留跟 xAI Realtime API 交握的流程本身不綁任何業務內容
function calling 機制留「AI 判斷資訊收集完 → 呼叫工具 → 存起來」這個機制留著
記憶功能留記住使用者常用資料、下次代入，這是通用能力
四種表單定義砍一對一／引薦單／來賓／感謝金額，這四種連同必填欄位定義整包不要
人設指令文字砍「你是＿分會的語音助理」這類寫死的角色設定文字整段換掉
聯絡人別名清單砍原本用來校正同音錯字的「會員姓名清單」，改成用不到就先不做，或換成使用者自己的通訊錄

2換血後的核心差異：從「寫死表單」變「設定驅動」

原本四種表單、每種要填什麼欄位，是寫死在程式碼裡的。通用版要改成設定檔驅動——助理要收集什麼資訊、人設要講什麼話，寫在一份設定裡，不寫在程式邏輯裡。以後要改助理的用途，改設定檔就好，不用動程式碼。

原本（寫死）通用版（設定驅動）
VOICE_FORMS = { one_on_one: [...], referral: [...] } collectSchema = 從設定檔載入，欄位跟表單類型都是資料，不是程式碼
AGENT_INSTRUCTIONS 整段寫死中文人設 人設文字也是設定檔的一部分，可替換

4一句話

留下來的是「怎麼驗證身分、怎麼跟語音 AI 交握、怎麼用工具收資料、怎麼記憶」這套機制。原本寫死的四種表單跟人設文字整包換成一份可以替換的設定檔，助理要做什麼用途，改設定檔就好。
